## 两个实际发现并修复的问题

1. CSV重复列名：DictReader会保留后一个同名字段，可能静默改变患者性别等值。新增表头唯一性检查，发现重复列名直接拒绝该批次。修复前对应测试失败，修复后通过。
2. 清单漏哈希：原加载器只校验清单已经列出的文件；删除某个必需文件的哈希条目后，仍会继续加载。现在要求9张模型表JSON/Parquet、3个ODS和处置账本全部有哈希，且来源表清单恰为约定三表，在连接数据库前检查。该检查用于完整性保障，不是数字签名或来源身份认证。

修复前证据：[before-fix.txt](before-fix.txt)，首次12个用例中2失败、10通过。之后增加了一个数据库不可用恢复用例；最终[全项目结果](test-results.txt)为45通过。

## 恢复操作

先看出错阶段和清单，不删除旧成功批次。

- 源文件/文件落盘失败：修正来源或恢复存储条件，使用新run_id重跑；失败目录留作追溯，禁止覆盖同名目录。
- 文件SUCCESS但数据库失败：确认数据库可连接，再加载已经成功的目录，避免再生成一份源快照。
- 已加载的相同批次：返回ALREADY_LOADED；不会把当前指针退回旧批次。这不是用户可用的版本回滚命令。
- 相同run_id但内容改变：拒绝；应追查来源或使用新批次，不改动历史清单来绕过校验。

```powershell
# 项目根目录，恢复数据库连接
.\.venv\Scripts\python.exe -m scripts.local_postgres start
# 重试已有成功快照（本项目当前主批次）
.\.venv\Scripts\python.exe -m src.database.synthea_store --run-dir output/synthea/runs/stage-c-verified
# 故障测试使用临时文件和随机隔离schema
$env:RUN_DATABASE_TESTS='1'
.\.venv\Scripts\python.exe -m pytest tests/test_synthea_reliability.py -q --tb=short
```
