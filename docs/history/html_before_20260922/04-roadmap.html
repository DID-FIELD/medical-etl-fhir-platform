实施前要定下的五个设计选择

1. 患者维度覆盖全部患者，还是影像队列？

建议完整患者维度覆盖所有有效患者，影像队列作为查询条件；没有检查者可展示零检查。探索版只有 96 位影像患者，不能直接当成完整维度。

2. 检查事实以什么为主键？

优先使用源检查标识，而非“患者 + 日期 + 类型”。同一患者同日同类型可能有多次合法检查；影像实例另留关联。

3. 主链路先落在哪里？

优先复用 PostgreSQL 连接 API；文件快照用于验证处理逻辑及对账。数据库连接恢复前，不宣称数据库链路通过。

4. FHIR 使用哪个具体版本？

已统一R4B 4.3.0，以ImagingStudy表示检查摘要，具体映射和数据边界见第八章。

5. 首次采用快照还是增量？

先完成可重跑快照和成功批次发布机制。增量 upsert、迟到数据和维度历史另作设计，避免把快照重跑说成 CDC。
