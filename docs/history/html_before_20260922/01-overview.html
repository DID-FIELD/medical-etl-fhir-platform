业务目标与规划

把零散医疗记录，变成可以解释的数据服务

回答一个具体问题：这个患者在哪次就诊中做了哪些检查？一共做了几次？最近一次是什么时候？

源数据分散在患者、就诊、影像表中。项目负责接入、校验、标准化、关联、分层和查询，同时记录每次处理的来源与结果。它主要展示数据工程能力。

业务结果患者检查概览、按日期及模态统计检查量。
工程结果可重复运行、数量能对账、异常能定位。
复习目标讲清输入规模、实际产出、流转和问题处理。

这些技术各自做什么？

组件在项目中的职责需要避免的误解
Python / Pandas读取数据、转换字段、质量检查和小规模批处理代码可运行不代表数据语义正确
PostgreSQL已作为新主链路落地和 API 查询源建了表不代表已写入和核对数据
Parquet / Spark列式文件存储；完整 CSV ETL 与 Python 同口径对照已通过使用 Spark 不等于已验证集群规模
FastAPI把数仓结果按接口提供给应用接口存在不代表后端整条链路已跑通
FHIR按明确版本映射医疗交换资源JSON 能输出不等于符合全部标准与业务语义
Airflow调度任务、管理依赖与重试自动重试不能弥补非幂等的数据写入
