## 第一阶段：医疗项目完善与实测（当前优先）

### 必须回答的问题

1. 数据来自哪里？是公开数据、合成数据还是原有样例？包含哪些表、字段、业务实体，使用条件是什么？
2. 输入多少文件、多少字节、多少条记录、多少个不同患者和检查？患者数与检查数不能混用。
3. 每一步读入多少、保留多少、隔离多少、去重多少，最终各层和 FHIR 分别产出多少？条数变化为什么合理？
4. 如何通过批次 ID、源文件、源记录标识和业务键追踪一条记录从源数据到结果？失败在哪里、能否重跑、是否产生重复？
5. 实际运行耗时、运行环境和测试规模是什么？哪些组件真正运行过，哪些仅完成代码或设计？
6. 遇到了什么真实问题？如何发现、定位、修复和验证？不能把假设问题写成实际经历。

## 面试准备补充：如何将医疗数据工程经验迁移到自动驾驶场景

用户没有自动驾驶相关实践经验，面试中被问到如何将过去的经验迁移到新的业务环境。关注图像、传感器信息、位置与空间坐标，以及序列融合和时间同步，是为了理解合理的数据入仓流程和训练数据供给方式，准备有依据的设计回答，不是要建设自动驾驶项目。

面试练习需要理解和回答：

- 场景/行程/序列/帧/传感器的实体关系与数据粒度如何设计。
- 多传感器时间戳、同步窗口、缺帧和坐标系/标定版本如何记录及校验。
- 原始图像等大文件与结构化元数据如何分开存储，通过 URI、校验值和版本关联。
- ODS、DIM、DWD、DWS、ADS 如何映射到该场景，哪些操作属于数仓，哪些属于感知预处理。
- 如何按场景、天气、目标类型、时间、位置等条件筛选，生成训练样本清单与训练数据版本。
- 如何划分训练/验证/测试集、防止同一序列的数据泄漏，并支持可复现读取。
- 如何分析覆盖率、缺失率、同步偏差、类别分布与样本质量。

交付以流程解释、医疗与自动驾驶概念映射、场景设计题和面试回答为主。不要求下载自动驾驶数据集、搭建新平台或实现融合算法。回答应明确区分“医疗项目中实际做过的能力”“可迁移的设计方法”和“需要向领域同事确认的专业细节”，不能把方案表述成已有自动驾驶项目经验。先扎实完成医疗项目实测，再结合其真实经验组织迁移回答。

## 初步代码审阅发现（待复现与修复）

- 质量检查失败时，主流程仅输出 warning，之后仍继续入库。
- 主流程按 EMR 每行生成 Patient，多次检查可能重复产生同一患者资源；需要验证资源数量和 ID 唯一性。
- 主流程与 Airflow 分步流程的 ODS EMR 输入处理不同，需要统一数据语义与追溯口径。
- PostgreSQL 初始化了 DWS/ADS 表，但主 ETL 未见填充步骤，不能仅根据建表或 API 代码宣称完整链路已跑通。
- 多次独立连接执行 truncate/insert，需验证中途失败是否留下部分结果及重跑行为。

以上是代码检查发现，不应直接包装为已修复或已实测的项目经历。
